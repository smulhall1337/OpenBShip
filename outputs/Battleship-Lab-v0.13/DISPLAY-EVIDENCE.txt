Classic palette and persistent damage evidence — checkpoint 10, 2026-11-06

Identity and method
All native addresses apply only to supplied Full-RIP Bs.exe, PE32/i386, base
0x00400000, 397824 bytes, SHA-256:
B9A8AEFD1E5CED839670DF69B47C596175F38A3C99E33E584FFDD32D2006A569
The project has not patched it. Read-only code/data inspection and isolated
numerical execution support these new readable implementations. They are not
recovered original source or proof of complete original-game operation.

Gameplay palette data — high confidence for mutable entries
Classic entry at 0x42314B pushes "island.col" and calls loader 0x42A780 at
0x423150. That loader reads 768 bytes into 0x4FB3E0, then 0x42A7D6..0x42A840
patches 15 bytes. Relative RGB-byte offset -> replacement:
51:166, 52:178, 53:198, 54:206, 55:215, 56:227, 57:138, 58:150, 59:174,
39:13, 30:255, 31:255, 32:255, 40:114, 41:255.
ClassicPalette.Patched clones the source and applies exactly those stores.

Palette application at 0x401D40 loads system palette entries when creating the
DirectDraw palette, then copies source RGB entries 10..245. Later updates call
SetEntries with start 10 and count 236 (0xEC). The byte channels are copied directly;
there is no inferred VGA six-bit expansion. Therefore applying all 256 ISLAND.COL
entries would incorrectly replace the reserved endpoints with placeholder greens.

The Recovered gameplay profile uses patched ISLAND.COL for 10..245. The remaining
20 entries are fixed to endpoint RGB values observed in a local GDI probe. That
probe returned zero entries while writing the endpoint buffer; its returned count
is explicitly not treated as a successful 256-entry API read. Only its observed
endpoint data is retained in Palette/Observed-Reserved-Endpoints.rgb, with the
actual log in System-Palette-Observation.txt. The source of these values and
ClassicPalette.cs state that they are a deterministic modern boundary, not an
original Windows 95/1997 desktop palette capture. Complete historical endpoint,
wrapper, fade timing and display-state fidelity remain unconfirmed.

The accepted embedded E_CLASS.PCX palette remains default. The Display menu lets
users compare the recovered mutable palette without losing the earlier appearance.
Changing colors rebuilds background, fleet, ship and damage bitmaps, swaps the
complete resource set only after success, then disposes the previous set. Game
state, shots, HP, target settings and visual phase are preserved. Settings changes
pause an active battle and require explicit Resume/P.

Fade arithmetic — independently checked, scheduling not implemented
0x422BA0 initializes fade-in factor 12; 0x422BC0 initializes fade-out factor 64.
0x422C70 multiplies each source byte by factor, divides by 64 with integer
truncation, and writes an output palette. If factor <64 it increments by 4 and
returns incomplete; otherwise it returns complete. 0x422C10 is the fade-out path,
decrementing by 4 until zero. The main loop dispatches these outside the Classic
40 ms gameplay limiter. Its effective display/flip cadence remains unresolved.
The port exposes/test-checks the byte arithmetic but does not invent an automatic
startup/exit fade duration or claim those transitions are fully reconstructed.

Tools/ClassicPaletteOracle.cs verifies the executable identity and copies only
patch block 0x42A7D6..0x42A840 and fade-in arithmetic 0x422C70..0x422CCD into its
own x86 process. It validates every relocated palette address/call operand. A small
local prologue recreates the original patch-block stack frame; the graphics API
call is replaced by a local return. Code becomes execute/read after writing;
input/output data remains separate. No original game, process, file, registry key
or desktop palette is altered. It emits Patched-Island.rgb, 65 fade RGB files and
a factor/return-state/hash CSV. All 768 patched bytes and every byte at factors
0..64 match ClassicPalette.cs. These are numerical cases, not 65 gameplay scenes.

Classic persistent damage — recovered asset, placement and frame selection
The Classic initializer makes fleet type 1. Its current-fleet path at 0x409271
calls 0x408540, which calls ship/damage draw 0x40D640 for the player's fleet. Other
fleets use the cell/UI path; their large hidden ships/damage are not disclosed.
At 0x40DB39..0x40DCC0, each surviving ship segment whose cell code is 8 receives a
persistent effect. Native fleet pointers disappear on sinking, ending that draw.

Type-1 Classic chooses sprite bank 15 (pointer 0x5630CC), loaded from "smoke.sph"
at 0x42AB14. Type-2 and type-9 alternate branches use other resources and are not
implemented as Classic smoke. SMOKE.SPH has 34 slots: 33 present frames, sentinel
slot 33 absent. All present frames decode exactly with no trailing bytes under the
bounded reader; original first-frame dimensions are 16x47.

For segment index i and native frame counter T:
    frame = (T + 8*i) % 33
Cell world coordinates are projected by the recovered flat Classic transform.
The effect anchor adds trunc(117/6)=19 to screen X and no extra Y. Scale is the
same integer 79% as the ship path. Native draw mode 2 centers horizontally and
aligns the bottom; SPH header origins are not added in this mode. The scaled
reader preserves the native per-row skip/run and 16.16 sampling behavior.
For cell (2,4), anchor is (164,331). Frame 0 scales to 12x37, with draw rectangle
(158,294,12,37). Damage is drawn following its ship in roster order. Modern hit
crosses/circles remain separate overlays; original transient weapon and movie
feedback is not reproduced by this persistent effect.

Visual cadence and intentional changes
The Classic solo loop increments 0x4B4220 and waits for timeGetTime deltas >=40 ms
at 0x423210..0x42325D. 0x4222A0 imports timeGetTime. This supports a 25 Hz target,
not an exact measured original presentation rate under every workload.
EffectClock targets 40 ms steps independently of rendering and turns. It caps
catch-up at 200 ms/five frames per update. Modern pause, focus loss, the map tab,
still preference and terminal state freeze advancement; F2 resets phase to zero.
Native global phase/performance scheduling and its pause behavior are not claimed
identical. Color changes retain phase. Still mode holds the current frame rather
than silently stopping gameplay or hiding known damage. This clock never consumes
RNG, changes turn progression or changes HP. The default 600 ms opponent timer is
unchanged and remains modern design.

Settings and input
DisplaySettings reads legacy sound=false correctly, adds colors/motion values,
preserves unknown key/value pairs and atomically replaces its per-version file.
Malformed values retain safe defaults with a visible status message. Failed display
resource construction retains the old resource set; failed persistence is reported.
The Display control supports native focused Enter/Space without sending the same
confirmation to the board; held confirmation is suppressed after popup closure.
Physical desktop key/menu/focus behavior remains a hands-on check.

Validation and limits
49 focused checks and 15 real-form checks pass. New checks cover numerical original
palette outputs, all 20 recorded endpoint values, native draw/resource constants,
33 frame boundaries, phase/anchor cases, hit/sink rendering, clock partitions,
pause/reset/catch-up, legacy mute and file preference round-trips. Form tests check

Input is simulated; audible output and full original-gameplay comparison remain
unconfirmed. Damage/color previews deliberately inject a labeled single hit and
use a fixed phase for comparison; they are not original gameplay observations.
