Modern implementation and intentional differences
P/Escape still toggle pause. While paused, End battle... opens an inline
confirmation with Keep battle focused by default. Confirming ends the current
battle and opens the original title. Cancel/P/Escape/tab/focus/reset invalidate
the captured confirmation owner. A stale callback cannot end another battle.
The original second-Escape trigger is not enabled; this explicit confirmation is
modern. Merely visiting the Original menu tab retains the paused battle as before.
After confirming End battle, Return to deployment describes the fresh blank
state; there is no advertised resume of the discarded battle. Settings persist.
Held Enter across the transition cannot activate Solo until released.

MainForm detaches the old Game/pending shot via the existing NewGame path.
ClipStudy.UnloadBattle stops the reusable output, drops PCM/timeline, detaches
canvas imagery and disposes the current/retiring frames. Shared application art,
fonts and the output component remain reusable until form disposal; this differs
from the original native allocation lifecycle. Reload, settings changes, late
pause/reset/step and failed loading handle the empty state explicitly. Unknown
clips fail visibly. No exception suppression or JIT configuration is used.
PauseActions owns only confirmation controls; MainForm validates game identity
and commits the transition. Simulation/AI/shot rules remain unchanged.
