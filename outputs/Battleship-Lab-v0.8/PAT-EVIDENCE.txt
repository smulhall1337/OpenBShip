Recovered framing and dimensions
The driver 0x402830 reads the current payload and the NEXT length together.
0x433930 reads a little-endian DWORD, not ASCII or a frame count. A record is:
DWORD payload length; four header bytes; encoded blocks. Length includes the
header but excludes its own DWORD. The last DWORD is 0xFFFFFFFF. The completion
return 6 follows the add/compare/sbb at 0x4028A4..0x4028AD. Zero is not the end
marker. BATFIRE1 has 46 records and consumes all 183558 bytes including its marker.
Every record's header is 20,15,4,4: 20x15 blocks of 8x8 pixels, 160x120 indices.
The scale dispatcher 0x4028B0 uses header byte +6; value 4 takes the fourfold
640x480 path. The fourth header byte's meaning remains unresolved. Its observed
value 4 is explicitly retained as HeaderVariant and enforced, not named as timing,
alpha or compression. Other headers/size/scale variants are rejected clearly.
Pixels are top-down, left-to-right, opaque palette indices. Each frame starts
from the previous frame's surface. The supplied first frame overwrites prior
surface contents independently: original decoding from zero and 0xA7 agrees.

Block decoder
Entry 0x433920 calls 0x433AA5. The latter sets width/stride, iterates block rows
through 0x433B59 and columns through 0x433B2D. Dispatch table 0x451875 contains
13 handlers, indexed by byte opcodes 0,4,...,48. Native invalid opcode skipping
is NOT copied: the bounded reader fails explicitly instead of hiding bad data.
0: fill 8x8 with one byte.
4: three prefix colors; two MSB-first two-bit quartet masks per row; selector 3
   escapes to a literal byte. Quartet functions are table 0x4540E1 (256 entries).
8: row flags choose solid first color or quartet decoding; third color is the
   low byte of the color/row-flags word. High byte supplies eight row flags.
12: 16 high-bit-first half-row flags choose first-color fill or quartets.
16: same half-row flags choose four literal bytes or quartets.
20: each vertical four-pixel half retains its last decoded quartet until updated.
24: each vertical half retains its quartet MASK; reuse still consumes any literal
    escapes. This is deliberately different from retaining decoded pixels.
28: seven prefix colors, eight LSB-first three-bit selectors per row; zero escapes.
32: row flags choose binary two-color rows or three-color/literal quartets.
36: two prefix colors, two-bit selectors; 2 repeats last literal, 3 updates it.
40: half-row flags select first-color fill or that adaptive two-color/latch coding.
44: retain all prior pixels in the block.
48: half-row flags select retained prior pixels or quartets.
Source handlers: 0x433D41..0x434C90 and 0x437EBD..0x437F9B. BATFIRE1 uses all
operations except 16; a separately constructed fixture covers all thirteen.
The implementation validates every read, header, frame boundary and exact payload
consumption. Limits: file <=16 MiB, payload <=65532 bytes, <=512 frames, only the
observed 20,15,4,4 variant. Missing/wrong markers, extra bytes, unsupported opcodes,
truncation and excessive counts fail explicitly. This is not a universal PAT codec.

Palette: correction to earlier preliminary notes
0x402732 tests application state 0x4FBDD4==2 and script state 0x457074!=0x29.
That branch expands bytes 30..737 of PAL by left shift 2 and replaces entries
10..245 (236 RGB triples). The alternate branch expands bytes 60..413 and updates
20..137 only (118 triples). Earlier v0.6 notes called this smaller branch the
gameplay palette without establishing the state condition; that description was
too broad. Both branches are now represented/tested explicitly. The study uses
the standard 236-entry movie branch. The source's 20 reserved Windows endpoints
retain the documented deterministic modern values. The smaller branch can be
computed by PatMovie.ClipColors(...,true), but is not silently substituted.
BATFIRE1 contains indices beyond 137, making this distinction visible. Its PAL
values are six-bit; conversion is *4 (maximum 252), without six-bit bit replication.
Display options affect the duel, not this explicitly composed study palette.

Independent validation
Tools/ClassicPatOracle.cs is an optional, source-built x86 fixture generator.
It requires exact hashes for Bs.exe AND the supplied LWEBS/BATFIRE1.PAT. It copies
only decoder arithmetic/handler spans and tables into its own allocation, validates
0/22/34/4 absolute relocations and all table pointers, and marks only code pages
executable. It never starts/attaches to the original game or calls original file,
graphics, video, sound or registry functions. A small exit trampoline records ESI
before popad; decoding instructions are unchanged. Input/output remain in separate
allocated data areas. Output canaries and exact consumed lengths are checked.
Only the trusted movie and explicitly constructed valid fixtures are executed by
this unbounded original code. Malformed inputs are tested against managed code.

All 46 managed frame hashes match original decoding. Complete indexed fixtures
for frames 0,20,45 also match. A 256-code quartet fixture confirms MSB-first selector
and natural left-to-right literal ordering. A two-frame solid-then-mixed fixture
tests every opcode, including unused-in-BATFIRE1 opcode 16, adaptive/latch behavior
and retained pixels/masks. These are grouped decoder comparisons, not hundreds of
independent gameplay scenarios. .idx files are raw 160x120 row-major indices.
PAT-AllOps-Input.pat and PAT-Patterns-Input.bin are constructed diagnostic inputs,
not original game files. Their expected outputs come from copied original code.
Extract-ClassicPat.ps1 separately reproduces twelve raw code/table spans plus
their address/hash manifest without executing the original.

Presentation and confidence boundaries
Classic 0x423210 enforces a minimum 40 ms loop and calls the frame driver once
per active iteration; 25 fps is the nominal cadence. The study holds each frame
for 40 ms, including the last, and reports completion after 1.84 s of normal
uninterrupted playback. Catch-up is capped at five frames/200 ms; pause, stepping,
focus loss and reset are explicit modern policy. The viewport letterboxes with
nearest-neighbor scaling, without reproducing desktop palette changes or every
original display mode. Historical performance/timing is not claimed identical.

49 focused checks and 15 real-form checks pass. New checks cover the decoder
fixtures, malformed/resource bounds, both palette paths, clock partitions/holds/
completion/reset, live playback and controls, battle isolation, focus-loss events,
minimum layout and disposed bitmap resources. Form events are simulated offscreen.
Two new actual-form clip previews were visually reviewed at normal/minimum sizes;
nine previous comparison scenes were regenerated for v0.7. Previews show frame
index 20 (UI frame 21), not a captured original game session. No-argument packaged
startup and clean close pass on the agent desktop. Physical playback/input and
perceived cadence remain useful user checks. No new audible result is claimed.
