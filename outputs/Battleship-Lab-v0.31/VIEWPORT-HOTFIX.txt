Fleet viewport / Start Game hotfix — v0.18.1 — 2026-11-07

User report: menu and Fleet Configuration open; clicking the original lower-left
Start Game does nothing. Git setup now succeeds; commit30264f0verified on main.

Cause established from actual supplied EC_FLEET.PCX header:640x512 storage.
FleetSetup.Render created a full512line bitmap, then FleetCanvas drew it into a
640x480 rectangle. Buttons used native coordinates without that squeeze. Thus
source button center(60,445) appeared at native viewportY417but hit atY445.
Source geometry/table/native asset bytes were correct; display cropping was wrong.

Reproduction: Check-FleetPointer.cs selects the screen on an owned offscreen
form, obtains the actual rendered bitmap dimensions and maps the artwork button
center through the rendered image. It sends WM_LBUTTONDOWN/UP only to its own
canvas. v0.18 produces Image640x512, inputY416, button-1, Started=False.
Corrected build produces Image640x480, inputY444, button2, Started=True.
Fleet-Click-v018-Reproduction.txt and Fleet-Click-Check.txt retain both traces.
The pixel's one-line truncation depends on canvas sizing; both lie within the
correct button after the crop. No capture/input-policy workaround was needed.

Correction: FleetProgram.Viewport validates640wide/480..512high source bounds,
then copies the first307200indexed pixels and palette into a640x480 surface.
FleetSetup draws ships/grid cursor/footprints onto that cropped surface before
scaling it. Original PCX and native hit regions remain unchanged. Visibility is
preserved if present; malformed/truncated backgrounds fail clearly.
